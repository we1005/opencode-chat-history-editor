# 完整消息展示修复

日期：2026-09-14。

## 现象与原因

用户反馈真实会话中大量消息被显示为“模型无响应或被用户终止”，但 OpenCode 原界面可见工具调用和明确错误。

原因在继承的展示代码：

1. `hasNoResponse = isAssistant && !reasoningContent && !textContent` 只检查正文 / reasoning 文本，并将整个工具渲染分支一起隐藏。
2. 没有渲染 `message.data` 中的 `error`，因此供应商原始错误被丢弃。
3. 将 parts 按类型合并，而不是保持原始顺序；空 reasoning、附件和其他类型没有显示。
4. `simplifyContent()` 隐藏长粘贴、代码和文件内容，再把 tooltip 预览截到 2,000 字，无法完整阅读。
5. 模型 / 供应商、结束原因、缓存 token 等信息缺失，数值条件渲染还会留下无意义的裸 `0`。

第一版的写入测试没有覆盖这些真实渲染分支，这是此前验收的遗漏。

## 回归方法

命令：`node --test frontend/test/message-rendering.test.mjs`。

使用真实的 React `MessageItem` 组件进行服务端 HTML 渲染，构造最小消息，检查原始错误、工具完整输入 / 输出、片段交错顺序、长粘贴末尾、空思考 / 附件 / 未知类型、部分正文与错误共存。

修复前：6 项全部因缺失预期内容失败。修复后：6 项通过。

测试仅使用合成数据，不把用户对话保存为测试 fixture。

## 修复

- 将会话操作、消息外层、片段展示、代码差异拆成独立组件。
- 每个 part 按来源顺序得到展示节点与原始 JSON 查看入口。
- 工具卡片始终展示；展开时完整挂载输入 / 输出，支持全局展开。
- 错误与正文 / 工具相互独立，展示实际名称与内容，不猜测失败原因。
- reasoning 即使没有文字也保留耗时与说明。
- 移除长内容简化 / 截断函数；大文本使用完整滚动区域。
- 原始 JSON 按需挂载，避免大对话默认把所有原文重复放进 DOM。
- 保留编辑入口、会话重命名 / 删除、用户消息导航及代码差异查看。
